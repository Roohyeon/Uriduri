# 우리두리(Uriduri) — PRD 요약
> 2026-11-18 · 원본: 03-spec.md (자세한 규칙·수용 기준은 원본 참고)
> 상태 표시: ✅ 로컬 모드로 구현됨 · ⏳ Supabase 연결 때 (묶음 5)

## 누가 · 왜
- **누가:** 데이트 사진은 많이 찍지만 꾸준히 기록하지 못하는 20~30대 커플, 특히 한 명이 기록하고 한 명은 반응만 하는 커플
- **왜:** 사진 1장과 한 줄로 10초 만에 "데이트 영수증"을 남기고, 상대는 스탬프로 반응해 둘의 기록이 되며, 서비스가 멈춰도 기록이 손에 남게 하려고

## 기능 목록
| # | 기능 | 한 줄 설명 | 상태 |
|---|---|---|---|
| R1 | 로그인 | 카카오·구글 계정으로 로그인, 로그인 직후 닉네임 입력 | ✅ 가짜 로그인 / ⏳ 실제 로그인 |
| R2 | 방 만들기·초대 링크 | 사귄 날을 고르고 방을 만들어 초대 링크를 카톡으로 보냄 | ✅ |
| R3 | 초대 수락·2명 제한 | 링크를 열고 로그인하면 입장, 세 번째 사람은 막힘 | ✅ |
| R4 | 영수증 발행 | 사진 1장 + 한 줄 메모(50자), 촬영 날짜 자동 입력, 장소·기분 선택 | ✅ |
| R5 | 영수증 목록(홈) | 데이트 날짜순 화이트보드, 안 본 영수증 NEW 표시, 카드 자리 옮기기 | ✅ |
| R6 | 스탬프 반응 | 상대 영수증에 도장(모양 3종, 문구 6자) 찍기 | ✅ |
| R7 | 수정·삭제 | 내가 쓴 영수증만 고치거나 지움 | ✅ |
| R8 | 이미지 저장·공유 | 영수증을 PNG로 저장하거나 카톡·인스타로 공유 | ✅ |
| R9 | 전체 백업 ZIP | 사진 + 인터넷 없이 열리는 기록 보기(HTML) + 데이터(JSON) | ✅ |
| R10 | 사진 비공개 저장 | 방 멤버만 임시 주소로 사진을 봄 | ⏳ |
| R11 | 보관 기간 제한 없음 | 기록을 기간 제한 없이 보관 | ⏳ |
| R12 | 사용 기록 | 작성 열기·발행·저장·공유를 기록해 4주 사용 검증 | ✅ |
| R13 | 방 삭제·로그아웃·탈퇴 | "삭제" 입력 후 방 삭제, 방이 없어야 탈퇴 가능 | ✅ |
| R14 | 휴대폰 브라우저 | 앱 설치 없이 휴대폰 브라우저 우선 | ✅ (실기기 확인 남음) |

**이번에 안 하는 것:** 월간 결산, 위시리스트·룰렛, 결제·광고, 푸시 알림·실시간 반영, 장소 자동 입력, 3명 이상 방·여러 방, 통계 화면, 데스크톱 최적화

## 화면 구성
| 주소 | 화면 | 주요 구성 |
|---|---|---|
| `/login` | 로그인 | 카카오·구글 버튼, "지난번엔 ○○로 로그인했어요" |
| `/welcome/nickname` | 닉네임 입력 | 닉네임 칸(10자), 다음 |
| `/welcome/anniversary` | 사귄 날 입력 | 날짜 선택 (초대받은 사람은 건너뜀) |
| `/room/new` | 우리 방(방 없음) | 방 만들기, "초대 링크를 받았어요"(링크 붙여 넣기), 다른 로그인 방식 의심 안내, 탈퇴하기 |
| `/room/created` | 방 만들기 완료 | 초대 링크 + 복사 |
| `/i/<token>` | 초대 수락 | "○○님의 방에 들어가요" + 수락, 링크 오류 안내(만료·사용됨·가득·다른 방) |
| `/` | 우리 보드(홈) | 화이트보드 전체 배경, D+ 표시, 영수증 카드, "새 영수증 N개" 띠, 연결 알림(5초), 발행 버튼 / 빈 화면 / 상대 대기 중 |
| `/new` | 영수증 발행 | 사진 고르기, 날짜(자동·수정), 메모, 장소, 기분, 미리보기, 발행 |
| `/r/<id>` | 영수증 상세 | 영수증(로고→날짜→FROM·PLACE·MOOD→사진→메모→TOTAL D+→STAMPS), 스탬프 찍기, 이미지 저장·공유, 수정·삭제(내 것만) |
| `/r/<id>/edit` | 영수증 수정 | 발행 화면과 같음, 도장 유지 |
| `/settings` | 설정 | 닉네임·사귄 날 바꾸기, 로그인 방식, 새 초대 링크(혼자일 때), 백업 ZIP, 방 삭제, 로그아웃, 탈퇴 |
| 그 밖 | 찾을 수 없는 화면 | 안내 + 보드로 가기 |

## 관련 문서 핵심 (한 줄씩)
- **기획 원본 (03-spec):** 요구사항 R1~R14와 수용 기준. 목표는 10초 기록, 스탬프 참여, 이미지로 내보내기, 백업, 4주 직접 사용 검증
- **디자인 방향 (01-direction):** "감열지 영수증" 콘셉트. 흰 종이와 검정 잉크에 빨간 도장 한 곳만 강조하고, 보조 글자는 바랜 보라(#5F5688), 영수증 안 숫자만 IBM Plex Mono, 나머지는 Pretendard
- **개발 핸드오프 (05-handoff):** 색·글꼴·간격 토큰과 컴포넌트 상태 명세. 남은 디자인 이슈: 빨강을 발행·삭제에 같이 씀, 로딩 모양이 보드와 다름, 작성 화면 스크롤이 김, 기분 아이콘에 이름 없음, 320px에서 NEW 배지가 날짜를 가림
- **개발 설계 (02-plan):** React + Vite + TypeScript + Tailwind. 화면은 `services/`만 부르고, 비밀 키 없이 DB 규칙(RLS)으로 막는 구조. 지금은 로컬 모드(localStorage + IndexedDB), Supabase는 마지막 묶음
- **구현 기록 (03-progress):** 묶음 1~4 완료(자동 테스트 34개, 브라우저 시험 통과). 남은 것은 Supabase 연결(묶음 5)과 아이폰 HEIC·공유 창·ZIP 실기기 확인

## 다른 컴퓨터에서 실행하기
1. Node.js 22 이상 설치
2. `git clone https://github.com/Roohyeon/Uriduri.git` → `cd Uriduri/app`
3. `npm install`
4. `public/config.example.js`를 같은 폴더에 `config.js`로 복사 (지금은 값을 비워 둬도 로컬 모드로 동작)
5. `npm run dev` → 터미널에 나온 주소(보통 http://localhost:5173) 열기
- 테스트 `npm test`, 빌드 `npm run build`
- 로컬 모드라 데이터는 그 브라우저에만 저장됨 (컴퓨터를 바꾸면 기록은 따라오지 않음)
